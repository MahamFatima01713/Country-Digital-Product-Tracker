# Country-Digital-Project-Tracker
A full-stack web application for tracking digital projects across multiple
countries in one place. Coordination teams working on national digital, data
and AI initiatives usually keep project updates in separate spreadsheets.
This application replaces that with a single register: every project is
logged with its country, owner, topic, status and next milestone, and a
dashboard shows the state of the whole portfolio at a glance.
The application was built as a portfolio project modelled on the
coordination needs of a multi-country programme team. All data in it is
sample data, created for demonstration. It is not an official system of
any organisation.
Features
Add, view, update and delete projects (full CRUD)
Portfolio dashboard with the total number of projects and counts by
  status: Not Started, Ongoing, Completed and Delayed
Filter the project list by country, by status and by topic
Project form with a fixed country list and fixed topics (Digital, Data,
  AI), so entries stay consistent and comparable across countries
Input validation on the API: a status outside the four allowed values,
  or a missing required field, is rejected with a clear error
Sample dataset of 10 projects across different countries and topics,
  loaded with one command, so the dashboard can be explored immediately
Interactive API documentation, generated by FastAPI, at /docs
Tech stack
Backend: Python, FastAPI, Uvicorn
Database: MySQL, accessed through SQLAlchemy with the PyMySQL driver
Frontend: HTML, CSS and vanilla JavaScript, using the Fetch API to talk
  to the backend
Configuration: python-dotenv (settings and the database password live in
  a .env file, never in the code)
  Project structure
country-digital-project-tracker/
|-- README.md          this file
|-- requirements.txt   Python packages for the backend
|-- .env.example       example settings file (no real values)
|-- .gitignore         keeps .env, venv and cache files out of Git
|-- database.py        MySQL connection, engine, session factory, Base, get_db
|-- models.py          the projects table, defined with SQLAlchemy
|-- schemas.py         request and response schemas (validation rules)
|-- main.py            FastAPI application: all endpoints, CORS, serves the page
|-- seed.py            loads the 10 sample projects into the database
|-- index.html         dashboard page: counts, filters, project table, form
|-- style.css          page styling
`-- app.js             page logic: fetch calls for listing, adding,
                       editing and deleting projects
How the parts fit together: index.html and app.js call the API in
main.py. main.py validates input with schemas.py and reads and
writes rows through the Project model in models.py, using the session
and engine from database.py.
Getting started
You need Python and MySQL installed locally.
Clone the repository:
   git clone https://github.com/MahamFatima01713/country-digital-project-tracker.git
   cd country-digital-project-tracker
Create and activate a virtual environment (Windows):
   python -m venv venv
   venv\Scripts\activate
Install the packages:
   pip install -r requirements.txt
Create the database in MySQL:
   CREATE DATABASE undp_tracker;
Create your settings file. Copy .env.example, rename the copy to
   .env, and put your own MySQL password in it:
   MYSQL_HOST=localhost
   MYSQL_USER=root
   MYSQL_PASSWORD=your_mysql_password
   MYSQL_DB=undp_tracker
   .env is listed in .gitignore. Do not commit it.
Create the table and load the sample projects:
   python seed.py
Start the application:
   uvicorn main:app --reload
Dashboard: http://127.0.0.1:8000
API documentation: http://127.0.0.1:8000/docs
Using the dashboard
The top of the page shows the total number of projects and how many are
in each status. Below it, the filters narrow the table by country, status
or topic. The form on the page adds a new project; every row in the table
can be edited or deleted, and the dashboard counts update with every
change.
Testing
The application was tested manually with three mock "country office"
users. Each user was asked to add a project and then update its status,
and the time to complete the update was recorded as the success metric.
Findings and fixes are summarised in the testing report that accompanies
this project, along with its PRD and roadmap documents.
